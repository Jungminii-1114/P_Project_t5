### 단계 4. 오류 수정 (F1~F7)
각 항목마다 `tests/`에 재현 테스트를 먼저 추가한다. 테스트는 **API 호출 없이** 돌아가야 한다(LLM·임베딩은 mock/fake).

**F1. 표 행 요약에서 서로 다른 열의 같은 값이 사라짐** (`dedup_cells`, `row_summary`, `parse_table`)
- 재현: 헤더 `| 모집단위 | 일반전형1 | 일반전형2 |`, 행 `| 가상학과 | 30 | 30 |` → 현재 요약은 `일반전형2=30`만 남는다.
- 기대: `- 가상학과: 일반전형1=30, 일반전형2=30`
- 방향: 값 셀(`is_value`)은 중복 제거 대상에서 빼고, 라벨 쪽 반복(병합 셀에서 복제된 라벨)만 합친다. 열 정렬이 깨지지 않게 한다.
- 회귀 확인: 수정 전후로 513개 청크 전체의 행 요약을 비교해 **바뀐 청크 수와 예시 3개**를 보고서에 남긴다.

**F2. 근거 검증이 사실 연결을 확인하지 않음** (`ground_answer`, `make_confidence`)
- 재현 ①: 근거 `경영학과 30명`, `간호학과 15명` / 답변 `경영학과 15명` → 현재 `score=1.0`.
- 재현 ②: 인용 `(출처: 03_없는파일.pdf p.104)`가 실제 `03_2027학년도_수시_모집요강.pdf p.104`와 앞 두 글자·페이지만 같아 통과한다.
- 기대 ①: 답변의 같은 문장 안에 있는 (개체, 숫자/날짜) 쌍이 근거의 **같은 줄·같은 표 행·같은 문장**에 함께 있어야 통과. 아니면 점수를 낮추고 교정을 유도한다.
- 기대 ②: 인용은 정규화한 파일명 전체 + 페이지가 일치해야 통과.
- `conf`는 확률이 아니므로 이름을 `heuristic_score`로 바꾸고, 노트북 설명에서도 "신뢰도/확률" 표현을 쓰지 않는다.

**F3. 답변 유보를 막는 프롬프트** (`DRAFT_PROMPT`, `REPAIR_PROMPT`)
- 삭제: `NEVER say a rule or information is absent when any evidence passage mentions the question's key terms.`
- 수정: `REPAIR_PROMPT`의 `The evidence DOES contain sentences relevant to the question.`를 "근거를 끝까지 확인하되, 없는 부분은 지어내지 말 것"으로 바꾼다.
- 추가: 질문의 일부만 근거에 있으면 **있는 부분은 답하고, 없는 부분만 "제공된 문서에서 확인할 수 없습니다"라고 명시**한다.
- 재현 테스트는 프롬프트 문자열 검사 수준으로 충분하다. 효과는 단계 6 평가로 확인한다(Drive #20의 기숙사비 부분이 해당 사례).

**F4. 18초 상한이 LLM 대기에만 걸림** (`ask`, `retrieve_multi`, `retrieve_more`, `_call_llm`)
- 재현: fake 시계 또는 느린 fake 검색기·LLM으로, 검색·분해 검색·추가 검색이 오래 걸릴 때 전체 시간이 18초를 넘는 것을 보인다. 추가 검색이 `REPAIR_START_LIMIT`(9초) 이후에도 실행되는 것도 보인다.
- 기대: 요청 시작 시 만든 **하나의 deadline**을 모든 단계에 넘긴다.
  - `retrieve_multi`: 하위 검색 future에 남은 시간 기반 timeout. 시간이 모자라면 끝난 결과만 쓴다.
  - `retrieve_more`·교정: 남은 시간이 기준보다 적으면 시작하지 않는다(`meta["action"]`에 `_skipped` 기록).
  - LLM 호출이 timeout되면 이전 답변(초안)을 유지한다. 초안조차 없을 때만 FALLBACK 문구를 쓴다.
- 테스트: 어떤 느린 조합에서도 `ask()`가 19초 안에 반환됨을 fake 시계로 검증한다.

**F5. 입력 문서 고정과 기록** (`prepare_dataset`, 파싱 루프)

**F6. "홈페이지 주소" 검색 실패** (`SYNONYMS`)
- 문서에는 `www.gachon.ac.kr`이 있지만 "홈페이지" 질의로 검색되지 않는다.
- 일반 동의어 `"홈페이지": "www 누리집"` 수준만 추가한다. **실제 URL 같은 문서 값은 넣지 말 것.**
- 단계 6에서 회귀가 없는지 확인한다. 회귀가 생기면 되돌리고 기록한다.

**F7. 평가 로그 불완전**

### 단계 5. 평가 러너
`scripts/run_eval.py`를 만든다.
- 사용법: `uv run python scripts/run_eval.py --version v23 --sets sample3,hard20,holdout10,drive20 --repeat 1`
- `--version`에 따라 `pipeline_v22` 또는 `pipeline_v23`을 import한다. 색인은 실행마다 새로 만든다(이 시간은 측정에서 제외).
- `sample3`은 `sample.json`의 질문과 `sample answer`를 gold로 쓴다.
- 채점기는 v22와 **완전히 같게** 둔다(비교 가능성 유지). 같은 LLM, 아래 프롬프트와 스키마 그대로:
  ```python
  class Verdict(BaseModel):
      correct: bool = Field(description="예측 답변이 정답의 핵심 정보(수치·날짜·대상·조건)를 모두 포함하면 True")
      reason: str = Field(default="", description="판정 이유")

  JUDGE = """정답과 예측 답변을 비교하세요. 표현이 달라도 핵심 정보(수치·날짜·대상·조건)가 모두 일치하면 정답입니다.
  부분점수는 없습니다. 하나라도 빠지거나 틀리면 오답입니다."""
  # 입력: f"[질문]\n{q}\n\n[정답]\n{gold}\n\n[예측]\n{pred}"
  ```
- 산출물: `runs/<timestamp>_<version>/` 아래 `results.jsonl`(F7 항목 전부), `summary.json`(세트별 정확도·평균·최대·>5s·>10s·>19s), `env.json`(Python·패키지 버전, 문서 manifest, 모델명).
- 문항 사이 오류가 나도 중단하지 말고 그 문항을 실패로 기록한 뒤 계속한다.
- 응답시간 점수도 계산한다(정답 문항만: 5초 이하 0.4점, 5초 초과분 초당 0.08점 감점, 10초 이상 0점).
