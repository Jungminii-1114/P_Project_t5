## 파싱·검색의 구조적 한계

- **다단 헤더 분할**: `split_table_markdown`은 표 첫 두 markdown 행을 반복 헤더로 고정한다(`:460–475`). pdfplumber 표에서는 추가 헤더 행이 본문 행처럼 처리될 수 있어, 표가 여러 청크로 나뉘면 뒤 조각에 추가 헤더 정보가 반복되지 않는다.
- **병합 셀·기호·선 없는 표**: HWP 병합셀은 제한된 규칙으로 펼치고, 표 구조가 불완전하거나 선이 없는 표는 셀의 열 대응과 의미를 복원하지 못할 수 있다. `★` 등 기호가 포함된 셀만으로 행·열 의미를 결정할 수 없다.
- **문서 제목 계층**: 본문에서 장·절의 부모-자식 경로를 추출하지 않는다. 문맥 헤더의 문서 제목은 파일 접두사 기반이며 섹션 경로를 제공하지 않는다.
- **HWP page 값**: HWP 본문은 `page=1`, 표는 `element_index+1`을 기록한다(`:385–401`). 실제 인쇄 쪽 번호가 아니며 표의 요소 순번에 가깝다.
- **시작한 스레드의 취소**: deadline 만료 시 future 대기는 중단되지만, 이미 실행 중인 Python 스레드를 강제로 종료하지는 않는다(보고서 §39). 대기 응답 시간 제한과 실제 작업 중단은 같지 않다.

## 평가·검증 범위

- hard20, holdout10, drive20은 모두 개발 과정에서 사용됐다(보고서 §33). sample3 반복도 작은 고정 세트다. baseline-1 수치는 독립적인 일반화 성능으로 볼 수 없다.
- v22의 이전 Colab 집계와 로컬 비교 수치는 다르다. 보고서는 v22 holdout10의 10/10(§29)과 로컬 실행의 6/10(§36)을 별도 실행으로 구분한다. 지연·judge 변동 때문에 v23 결과를 특정 수정 하나의 인과 효과로 단정하지 않는다.
- 노트북 실행 확인은 새 Python 프로세스에서 코드 셀을 `exec()`로 순서대로 실행한 검사다(13개 코드 셀, 오류 0, 보고서 §35). Jupyter 커널과 Colab에서 실행 확인하지 않았다.
- 홈페이지 주소 smoke는 답변 인용 페이지에 같은 주소가 존재함을 확인했지만, 주소 자체를 원본 문서와 별도로 검증하지 않았다(보고서 §36).
- 저장 노트북의 gold 8자 조각 중복 검사 기준은 0건을 충족하지 못했고, 비교 결과의 `all_plan_checks_passed`는 false다. 보고서 §35는 기존 일반 표현·문서명과 새 유보 문구가 일치 조각의 원인이라고 설명한다. 이는 8자 조각 검사 결과이며, 구체 정답 수치 유출과 같은 의미로 해석하지 않는다.
